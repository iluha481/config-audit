# config-audit

`config-audit` — консольная утилита на Go для проверки конфигурационных файлов YAML и JSON на потенциально опасные настройки. Программа находит проблемы, присваивает им уровни `LOW`, `MEDIUM` и `HIGH`, выводит краткое объяснение и рекомендацию, а также завершается с кодом `1`, если найдена хотя бы одна проблема (если не указан `--silent`).

Утилита рассчитана на конфигурации с заранее неизвестной схемой: анализ выполняется по именам ключей, их суффиксам, пути в дереве, контексту родительских секций и значениям.

## Возможности

- Поддержка JSON (`.json`) и YAML (`.yaml`, `.yml`).
- Проверка отдельного файла, директории или данных из стандартного ввода.
- Декларативный набор правил: правила хранятся в JSON или YAML и не требуют изменения кода.
- Уровни критичности `LOW`, `MEDIUM`, `HIGH`.
- Краткое описание проблемы и рекомендация по исправлению для каждой находки.
- Сортировка находок: сначала по критичности, затем по строке и пути.
- Коды возврата, позволяющие использовать утилиту в CI и скриптах.
- Флаги `-s`/`--silent` и `--stdin`.
- Дополнительно: рекурсивная проверка директории, пользовательские правила и проверка прав доступа к файлу конфигурации.

## Требования

- Go 1.27.3 или новее.
- Единственная внешняя зависимость — `gopkg.in/yaml.v3`. Она устанавливается автоматически при сборке.

## Сборка

Из корня репозитория:

```bash
go mod download
go build -o config-audit ./cmd/config-audit
```

Запуск без сборки:

```bash
go run ./cmd/config-audit --help
```

## Быстрый старт

Создайте тестовый файл `app.json`:

```json
{
  "version": "0.1",
  "log": {
    "output": "stdout",
    "level": "debug"
  }
}
```

Запустите проверку:

```bash
./config-audit app.json
echo "Код возврата: $?"
```

Пример вывода:

```text
LOW: логирование в debug-режиме [log.level]
     Рекомендация: Поменяйте режим на более избирательный (info+).
Код возврата: 1
```

Если проблем нет, выводится сообщение `Проблем не обнаружено.`, а код возврата равен `0`.

## Использование

```text
config-audit [параметры] <путь-к-файлу-или-папке>
config-audit --stdin [параметры]
```

Путь к конфигурации передаётся позиционным аргументом. При использовании `--stdin` позиционный аргумент не требуется.

### Параметры

| Параметр | Описание |
| --- | --- |
| `-s`, `--silent` | Не завершаться с ошибкой при наличии проблем. Находки всё равно выводятся. |
| `--stdin` | Прочитать конфигурацию из стандартного потока ввода вместо файла. |
| `-r`, `--rules <путь>` | Путь к файлу или директории с правилами. |
| `-h`, `--help` | Показать справку. |

Если параметр `--rules` не указан, программа последовательно ищет правила в следующих местах:

1. `rules/rule.json`
2. `rules/`
3. `../rules/rule.json`
4. `../rules/`

Если ни один из этих путей не найден, используется встроенный набор, поэтому утилита остаётся работоспособной и вне корня репозитория.

### Коды возврата

| Код | Значение |
| --- | --- |
| `0` | Проблем не найдено, либо указан `--silent`, либо показана справка. |
| `1` | Найдена хотя бы одна проблема. |
| `2` | Ошибка аргументов, чтения файла, разбора конфигурации или загрузки правил. |

## Примеры

### Проверка JSON-файла

```bash
cat > config.json <<'EOF'
{
  "version": "0.1",
  "log": {
    "output": "stdout",
    "level": "debug"
  }
}
EOF

./config-audit config.json
```

Вывод:

```text
LOW: логирование в debug-режиме [log.level]
     Рекомендация: Поменяйте режим на более избирательный (info+).
```

### Проверка YAML-файла

```bash
cat > config.yaml <<'EOF'
version: 2.2
storage:
  digest-algorithm: MD5
EOF

./config-audit config.yaml
```

Вывод:

```text
HIGH: слишком слабый алгоритм - MD5 [storage.digest-algorithm:3:21]
     Рекомендация: Замените его на более безопасный (например, SHA-256, AES-256-GCM, TLS 1.3).
```

### Чтение из стандартного ввода

```bash
cat config.yaml | ./config-audit --stdin
```

При использовании `--stdin` формат определяется по содержимому: JSON распознаётся по первому символу `{` или `[`, остальные данные обрабатываются как YAML.

### Проверка директории

```bash
./config-audit ./configs
```

Директория обходится рекурсивно. Проверяются файлы с расширениями `.json`, `.yaml` и `.yml`. Если отдельный файл не удалось разобрать, выводится предупреждение, а обработка остальных файлов продолжается.

### Режим без ошибки при находках

```bash
./config-audit --silent config.yaml
echo "Код возврата: $?"
```

Находки будут выведены, но код возврата останется `0`. Это удобно, если проверка используется как информационный шаг в CI.

### Пользовательские правила

```bash
./config-audit --rules ./rules/rule.json config.yaml
```

Можно передать директорию:

```bash
./config-audit --rules ./rules ./configs
```

При загрузке правил проверяются обязательные поля, корректность уровней критичности и уникальность идентификаторов. Файлы правил поддерживаются в форматах JSON и YAML.

## Проверяемые настройки

Правила по умолчанию находятся в `rules/rule.json`. Если файл недоступен, используется встроенная копия набора.

| Идентификатор правила | Уровень | Что проверяется |
| --- | --- | --- |
| `log.debug` | `LOW` | Включённый debug-режим логирования. |
| `credential.plaintext` | `HIGH` | Пароль, токен или секретный ключ в открытом виде. |
| `network.bind_all` | `MEDIUM` | Привязка к `0.0.0.0`, `::` или аналогичному неограниченному адресу. |
| `tls.insecure` | `HIGH` | Отключённая проверка TLS-сертификатов или отключённый TLS. |
| `crypto.weak_algorithm` | `HIGH` | Устаревшие и небезопасные алгоритмы: MD5, SHA-1, DES, RC4 и другие. |
| `perm.too_wide` | `HIGH` | Слишком широкие права доступа, заданные в конфигурации. |
| `perm.file_too_wide` | `HIGH` | Файл конфигурации доступен на запись всем пользователям. Проверка выполняется через `os.Stat` и не применяется к `--stdin`. |

Правило `perm.file_too_wide` формируется самой утилитой, а не загружается из файла правил.

Сообщения правил могут содержать подстановки:

- `{{path}}` — путь к узлу;
- `{{value}}` — значение узла;
- `{{key}}` — ключ узла;
- `{{line}}` — номер строки;
- `{{id}}` — идентификатор правила;
- `{{name}}` — имя правила.

## Формат правил

Файл правил содержит версию и массив правил:

```json
{
  "version": 1,
  "rules": [
    {
      "id": "log.debug",
      "name": "Debug logging",
      "severity": "LOW",
      "message": "Debug logging is enabled at {{path}}",
      "recommendation": "Set the log level to info or higher.",
      "match_mode": "any",
      "match": [
        {
          "keys": ["level", "log-level"],
          "context": ["log"],
          "operator": "in",
          "values": ["debug", "trace"],
          "ignore_case": true
        }
      ]
    }
  ]
}
```

### Поля правила

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `id` | Да | Уникальный идентификатор правила. |
| `name` | Да | Читаемое имя правила. |
| `severity` | Да | Уровень критичности: `LOW`, `MEDIUM` или `HIGH`. |
| `message` | Да | Краткое описание найденной проблемы. |
| `recommendation` | Да | Рекомендация по исправлению. |
| `enabled` | Нет | Если указано `false`, правило не применяется. По умолчанию правило включено. |
| `include_value` | Нет | Если указано `true`, в находку добавляется исходное значение узла. Используйте осторожно для секретов. |
| `tags` | Нет | Произвольные метки правила. |
| `target` | Нет | Зарезервированное поле. |
| `match_mode` | Нет | Режим объединения условий: `any` или `all`. По умолчанию `any`. |
| `match` | Да | Массив условий проверки. Должно быть хотя бы одно условие. |

### Поля условия `match`

| Поле | Описание |
| --- | --- |
| `keys` | Список имён ключей, с которыми сравнивается ключ узла. |
| `key_suffixes` | Список суффиксов, которыми должен оканчиваться ключ узла. |
| `path` | Путь к узлу в дереве конфигурации. |
| `context` | Список имён родительских секций, в которых должен находиться узел. |
| `operator` | Оператор проверки значения. Обязательное поле. |
| `values` | Значения или шаблоны, используемые оператором. |
| `ignore_case` | Сравнивать строки без учёта регистра. |
| `normalize` | Сравнивать ключи в каноническом виде: без учёта регистра, символов `_` и `-`. |
| `ignore_references` | Пропускать ссылки на переменные окружения и хранилища секретов: `${VAR}`, `$VAR`, `{{ secret }}`, `vault:...`, `env:...`, `secret:...`, `aws:...`, `sm:...`, `ref:...`. |
| `negate` | Инвертировать результат проверки. |

Условие должно содержать хотя бы одно из полей `keys`, `key_suffixes`, `path` или `context`.

### Операторы

| Оператор | Описание |
| --- | --- |
| `in` | Значение совпадает с одним из элементов `values`. |
| `equals` | Значение точно совпадает с одним из элементов `values`. |
| `contains` | Значение содержит одну из подстрок `values`. |
| `has_prefix` | Значение начинается с одного из префиксов `values`. |
| `has_suffix` | Значение оканчивается одним из суффиксов `values`. |
| `regex` | Значение соответствует одному из регулярных выражений `values`. |
| `exists` | Значение задано и не пусто. |
| `perm_too_wide` | Права доступа слишком широки: установлен бит записи для всех или режим равен `0777`/`0666`. |

Для операторов `in`, `equals`, `contains`, `has_prefix`, `has_suffix` и `regex` значения в `values` обязательны по смыслу правила. Неизвестный оператор не приводит к совпадению.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `cmd/config-audit/` | Точка входа, разбор аргументов, вывод результата и встроенный набор правил. |
| `internal/config/` | Разбор JSON и YAML в единое дерево узлов, ограничения на размер и глубину. |
| `internal/rule/` | Загрузка, проверка и представление правил. |
| `internal/audit/` | Движок проверки, сопоставление условий и формирование отчёта. |
| `rules/rule.json` | Правила по умолчанию. |
| `.github/workflows/ci.yml` | CI: форматирование, статический анализ, тесты и сборка. |

## Ограничения

- Для входной конфигурации действуют ограничения: 8 МиБ, глубина вложенности 200, не более 200 000 узлов.
- Размер файла правил ограничен 4 МиБ.
- Проверка прав доступа к файлу конфигурации выполняется только для файлов и не применяется к данным из стандартного ввода.

## Разработка и тесты

```bash
gofmt -w ./cmd ./internal
go vet ./...
go test ./...
go test -race ./...
go build ./...
```

CI-пайплайн в `.github/workflows/ci.yml` выполняет:

- проверку зависимостей через `go mod verify`;
- проверку форматирования через `gofmt -l .`;
- статический анализ `go vet ./...`;
- тесты с детектором гонок и покрытием: `go test -v -race -cover ./...`;
- сборку CLI без сохранения бинарного файла в репозитории.
